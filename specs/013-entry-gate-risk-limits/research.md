# Phase 0 Research: 進場閘門（回撤上限 + 結算日封鎖）

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-07-30

七個設計決策及其被否決的替代方案。本案的兩個最高風險
（閘門誤擋出場、狀態更新誤置於迴圈開頭）都在 D1、D2 收斂。

---

## D1：接線點 = AND 掉 `is_entry` / `short_entry`，不重新縮排、不用 `continue`

**Decision**: 在 `backtester.py` 開新倉判定區塊的尾端、`if is_entry:`（`:308`）
之前插入：

```python
if not gate_ok:
    is_entry = False
    short_entry = False
    # 記錄封鎖原因（FR-010）
```

**Rationale**: 三個候選位置的比較——

| 位置 | 擋不到出場？ | diff 大小 | 判定 |
|---|---|---|---|
| 迴圈開頭 `continue` | ❌ **會連出場與權益更新一起跳過** | 極小 | **災難級，否決** |
| 重新縮排整個進場區塊到 `if gate_ok:` 之下 | ✅ 是 | 巨大（~65 行位移） | 否決 |
| AND 掉兩個布林（本案） | ✅ 是 | 4 行插入 | **採用** |

第一個選項必須明確否決並留下記錄：`continue` 會跳過同一根的出場判定
（`backtester.py:426+`）與權益曲線 append（`:581`），結果是「封鎖期間停損不會執行、
權益曲線出現斷點」。這正是 spec Edge Cases 所稱「一道會擋住停損的風控比沒有
風控更糟」的具體形式，且它是最容易被想到的實作方式——所以必須寫下來。

第二個選項功能正確，但 65 行的縮排位移會讓 FR-009（逐筆位元不變）的人工複核
變得極其困難：reviewer 無法用肉眼區分「只是縮排」與「順手改了一行」。
在一個要求位元不變的變更裡，**diff 的可讀性本身就是安全屬性**。

**Alternatives considered**:
- **折進 `global_ok`**（`backtester.py:246`）：否決。`global_ok` 是三關價 + regime
  的合成布林；混入閘門後，消融時無法區分是哪一項造成差異，FR-010 的封鎖原因
  也無從記錄。
- **擴充 `check_entry_signal` 增一個維度**（spec 012 的做法）：否決。該函式是
  **無狀態純判定**（給定一根 K 線的數值 → 布林），而閘門是路徑相依狀態。
  把狀態塞進去會破壞它可用真值表測試的性質（`tests/test_short_side.py:38-83`
  的鏡像真值表正是建立在無狀態之上）。

## D2：峰值與遲滯狀態在迴圈**尾端**更新

**Decision**: `peak_equity` 與 `DrawdownGate` 的狀態在每根迴圈尾端、
權益 append（`backtester.py:581`）的同一處更新；閘門於**下一根**開頭讀取。

**Rationale**: 這讓「只用已收盤資訊」由**執行順序**保證，不需要 `.shift()`。
時序恰好與訊號一致：

```text
第 i 根迴圈開頭：讀取 gate 狀態（反映 i-1 為止的權益）→ 判定進場
                 讀 sig_row = iloc[i-1]（判定根）→ 成交於 row i 開盤
第 i 根迴圈尾端：算出當根權益 → 更新 peak 與 gate 狀態
```

若把更新搬到迴圈開頭（在進場判定之前），閘門就會用到「當根的權益」——
而當根權益取決於當根成交價，屬於決策時點不可知的資訊。**這是本案第二高風險**，
因為「先更新狀態再判斷」在直覺上更自然。SC-004 的篡改測試專門守這一點。

**為什麼不能預先向量化**（本案與所有既有濾網的根本差異）：
repo 現有濾網（regime / FVG / 量能 / 三關價）都只依賴價量，故可在迴圈前算成
一欄。回撤依賴權益，而權益依賴交易本身——**閘門封鎖 → 少一筆交易 → 權益路徑
改變 → 後續回撤改變**，是一個反饋迴路。它在數學上不是 df 的函數，
無法預先計算。

**推論（重要）**：spec 004 的「前綴一致性」不變式
（`build_indicator_frame(df[:i]).iloc[-1] == build_indicator_frame(df).iloc[i-1]`）
**不適用於本案**——那條契約是針對無狀態衍生欄。因此不得以「parity 測試沒抓到」
作為無看前偏誤的證據；本案的偏誤防禦完全由 D2 的執行順序 + SC-004 承擔。

**Alternatives considered**:
- **預先算一條「假設不干預」的權益曲線，據此決定封鎖日**：否決。那條曲線與
  實際（有干預）的權益不同，等於用「另一個宇宙」的回撤來封鎖這個宇宙的交易，
  且該曲線本身含未來資訊。
- **每根重算整條權益的峰值**：否決。O(n²) 且無必要——running max 是 O(1)。

## D3：遲滯用兩個門檻參數，不用固定冷卻期數

**Decision**: `DrawdownGate` 為兩狀態機，轉移條件：
`dd <= -dd_limit_pct` → BLOCKED；`dd >= -dd_resume_pct` → OPEN。
schema 強制 `dd_resume_pct < dd_limit_pct`。

**Rationale**: 沒有遲滯（單一門檻）時，回撤在門檻附近震盪會逐根翻動封鎖/解除，
產生大量無意義的狀態切換，且使消融結果難以解釋。

遲滯與冷卻期（blocked N bars）的比較：遲滯的兩個參數同量綱（都是回撤百分比），
語意一致、可一起校準；冷卻期引入「幾根」這個與市場無關的第三個旋鈕，
而且它的合理值取決於資料時框（日線 vs 5 分線完全不同），是隱藏的耦合。

**Alternatives considered**:
- **單一門檻無遲滯**：否決（flapping）。
- **固定冷卻期數**：否決（第三個旋鈕 + 時框耦合）。若實測顯示遲滯不足，
  再議——已寫入 spec Assumptions，不阻擋本案。
- **恢復門檻設為 0（回撤完全回復才解除）**：這是遲滯的特例，
  使用者可透過 config 達成（`dd_resume_pct: 0.0`），不需另立機制。

## D4：結算日由資料索引自行導出，不引入交易日曆套件

**Decision**: `settlement_days(index) -> set[date]`——對索引涵蓋的每個
（年, 月），取該月第三個週三；若該日不在索引的交易日集合中，取其後第一個
交易日。純函式、無狀態、可單獨測試。

**Rationale**: 三個好處：**(a)** 零新依賴——離線 CI 不得依賴外部行事曆服務；
**(b)** 「假日則後推」自動成立，因為判定基礎就是資料裡實際存在的交易日；
**(c)** 純函式可直接用構造資料測試 SC-006/SC-007，不需跑整支回測。

日內資料（5 分線）的處理：集合以 `date` 為單位，閘門比較
`sig_row.name.date() in settlement_days`。這使同一結算日的所有分鐘棒一致封鎖。

**Alternatives considered**:
- **引入 `pandas_market_calendars` 或 TAIFEX 行事曆 API**：否決。新增依賴
  （憲章 Governance 要求證成）且需要出網，而本案不需要——結算規則是純日期運算。
- **硬編碼結算日清單**：否決（違反憲章 V，且需人工維護）。
- **把結算日算進 `build_indicator_frame` 作為一欄**：可行但不採用。它與指標
  無關（不依賴價量），放進指標入口會擴大該入口的職責；且它需要 `asset_class`
  才知道是否適用，而指標入口刻意不知道資產類別。

## D5：封鎖原因採「條件輸出欄」，掛在 `equity_curve` 而非 `trades`

**Decision**: 任一閘門啟用時，`equity_curve` 的每根增一欄 `block_reason`
（未封鎖為空字串）；兩道皆關閉時**不輸出該欄**。

**Rationale**: 掛在 `trades` 的問題是——封鎖事件的本質是「**沒有**發生交易」，
放進交易日誌會製造「不是交易的交易列」，而 `_calculate_metrics`
（`backtester.py:617+`）以 `action` 欄分類統計交易，多出的列會污染勝率、
交易筆數等指標。掛在 `equity_curve`（逐根時序）語意正確：它記錄的是「這根的
狀態」。

**條件輸出**沿用 spec 012 D2 建立的模式（`include_regime` → `regime_ok`）。
安全性已核對：`_calculate_metrics` 只取 `df_equity['equity']` 與
`.get('position_value')`（`backtester.py:609-616`），既有測試只斷言
`res["equity_curve"]["equity"]`（`test_professional_upgrades.py:100`、
`test_real_data_integration.py:171`、`test_short_futures_e2e.py:58`），
無任何欄位集斷言。

**Alternatives considered**:
- **恆定輸出該欄**：否決。會改變預設狀態的 `equity_curve` 欄位集，
  FR-009 的位元不變就不再涵蓋欄位層面。
- **只記 log 不入資料結構**：否決。FR-010 要求可辨識，log 無法被測試斷言
  （SC-012 會退化成人工檢查）。

## D6：兩道閘門獨立開關 + 獨立消融鍵，共用一個出口

**Decision**: 參數層兩組獨立開關；`disabled_filters` 新增兩鍵
（`'dd_gate'`、`'settlement_gate'`），任一鍵存在時對應閘門視為恆開；
但兩者在引擎中合成單一 `gate_ok` 後接線一次。

**Rationale**: 「共用出口」是本案把兩個功能合為一 spec 的理由（架構上是同一件事：
一道不准開新倉的布林閘門）；「獨立開關」是 FR-008 要求分別歸因的必要條件。
兩者不衝突——合成發生在接線前一步。

**Alternatives considered**:
- **單一總開關**：否決。無法回答「是回撤閘門有用還是結算日閘門有用」，
  而這正是消融存在的目的。
- **兩個獨立接線點**：否決。重複 D1 的插入邏輯兩次，且未來若有第三道閘門
  會線性增長。

## D7：組合回測路徑（`portfolio_backtester.py`）範圍外，但須明確標註

**Decision**: 本案不在組合路徑實作閘門。閘門關閉時組合路徑行為不變，
即滿足 FR-009；若使用者對組合路徑啟用閘門參數，**須明確標註不支援**
（例如載入時警示），不得沉默忽略。

**Rationale**: 組合路徑有自己的迴圈與權益維護（`portfolio_backtester.py:99-135`
自行組裝指標、另有一套權益邏輯），在其中重複實作遲滯機會產生兩份狀態機——
兩份必然漂移。且該路徑本就僅限現貨、期貨護欄保留（CLAUDE.md 專案地圖），
而回撤閘門對高槓桿期貨的價值遠高於現貨。

「明確標註而非沉默忽略」是 spec 011 已建立的原則
（FR-008：期貨路徑缺欄硬失敗、不得沉默 fallback）——沉默忽略會讓使用者以為
風控在保護他，實際上沒有。這比不支援更危險。

**Alternatives considered**:
- **一併在組合路徑實作**：否決（兩份狀態機；範圍膨脹）。
- **沉默忽略參數**：否決（使用者誤以為有保護）。

# Feature Specification: 盤中時框評估協定（Intraday Evaluation Protocol）

**Feature Branch**: `016-intraday-evaluation-protocol`

**Created**: 2026-08-06

**Status**: Draft

**Input**: User description: "盤中（5 分線）時框評估正式化 —— 把一次性可行性探查升級為可重複、可驗證的評估流程，需回答 walk-forward 切分、逐標的統計、標的篩選準則、參數時框語意四件事"

---

## 背景與問題陳述

`docs/reviews/2026-08-06-intraday-timeframe-feasibility.md` 建立了一件事：
盤中資料**取得**不是障礙（yfinance 5m 上限為 60 天而非原先誤信的 5 天，
單檔約 3,130 根 / 59 交易日），8 檔台股實測合計 46 個來回交易、跨過推論門檻 30。

但該次探查**不是評估流程**，而是一次性診斷。它有四個結構性缺陷，
使其結論無法被引用、無法被重跑、也無法被反駁：

| # | 缺陷 | 具體證據 |
|---|---|---|
| 1 | **無樣本外切分** | 期間僅 2026-05-14 → 08-06 一個市況窗口 |
| 2 | **統計被 pooled** | 46 筆為 8 檔加總；五道合取率從 2308 的 2.1% 到 1301 的 15.8%，**7 倍差** |
| 3 | **標的為事後挑選** | 8 檔非 `config.data.tickers`（該清單為 2330/0050/00878/00919/00631L），係臨時選定，構成選擇偏誤 |
| 4 | **結論不可重現** | yfinance 對同一請求回傳浮動數值——0050 相隔 56 分鐘兩次執行得 7 → 5 個來回 |

另有一項**已被自身量測推翻但仍留在程式裡的處方**：
`run_5m_evaluation.py::verdict` 在交易數不足時輸出「先做參數時框化」，
但同一份實測顯示四道濾網單道通過率皆在 24–70% 正常範圍、無一因尺度失效。
該處方是假設，不是量測結論。

本規格把上述探查升級為**協定**：一組具名、可重跑、輸出帶邊界標示的評估程序。

---

## 已裁決事項

### D1：累積歷史存放於 Actions artifact，滾動累積（2026-08-06 裁決）

**選定**：每次排程執行取數 → 取回前次 artifact 的累積歷史 → 合併去重 →
上傳為新的 artifact（保留期設為上限 90 天）。累積歷史**不進版本庫**。

**已知代價，經裁決接受並記錄於此**：

1. **保留期上限 90 天**。這是平台硬上限，故累積鏈的存續取決於執行頻率——
   排程一旦中斷超過保留期，**整條累積歸零重來**。因此執行頻率須遠低於該上限
   （FR-022），且流程須能偵測並回報鏈結中斷（FR-023）。
2. **公開 repo 的 artifact 任何人可下載**。`.gitignore` 對 `data/` 的排除理由
   （「Yahoo Finance 資料公開再散布有授權疑慮」）在此**並未消解**，
   只是改由 artifact 承載同一風險。本規格不主張該疑慮已被解決。

**連帶**：`.github/workflows/probe_yfinance_5m.yml` 現行上傳 CSV 快照的行為
依同一裁決保留，並改寫為本累積機制的一環（FR-024）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 逐標的、可重現、帶邊界標示的評估報告 (Priority: P1)

研究者指定一份盤中資料快照與一組標的，取得**逐標的**的評估報告。
同一份快照重跑必得完全相同的數字；報告在每一個績效類數字旁明確標示
其推論效力邊界（樣本內／樣本外、樣本量是否足夠、是否允許跨標的合併）。

**Why this priority**: 這是協定的最小可用形態。沒有它，其餘三項都無處掛載。
它同時修掉缺陷 2 與 4——現況下任何人拿到報告都無法判斷數字能不能引用。

**Independent Test**: 對同一份固定快照連續執行兩次，逐欄比對輸出；
再對一份已知含 0 交易標的的快照執行，確認報告能說明 0 的成因而非僅顯示 0。

**Acceptance Scenarios**:

1. **Given** 一份固定的盤中資料快照，**When** 執行評估兩次，
   **Then** 兩次輸出的所有數值欄位逐欄相同（確定性）。
2. **Given** 多個標的的評估結果，**When** 產生報告，
   **Then** 每個標的各自一列統計，且任何跨標的合併數字必同時標示離散度
   （至少為極小值、極大值與比值）。
3. **Given** 某標的完成 0 筆來回交易，**When** 產生報告，
   **Then** 報告分解出該 0 落在哪一段：無結構訊號／有訊號但五道合取為 0／
   有候選但持倉互斥／有進場但資料結束前未出場。
4. **Given** 任一績效類數字（報酬、獲利因子、勝率、期望值），**When** 產生報告，
   **Then** 該數字附帶效力標籤，且在未通過樣本外驗證前標籤恆為「樣本內描述性統計」。
5. **Given** 評估執行完成，**When** 檢視輸出，
   **Then** 報告記錄輸入快照的內容指紋，使結論可與特定資料版本綁定。

---

### User Story 2 - 前置且客觀的標的納入準則 (Priority: P2)

標的清單由**事前、與評估結果無關**的準則產生，而非人工挑選。
準則本身可被檢驗、可被質疑、可被修改，且每次評估都記錄實際套用的準則版本。

**Why this priority**: 修掉缺陷 3。若標的仍為事後挑選，即使做到 walk-forward，
整體結論仍受選擇偏誤污染——這比樣本外切分更根本，因為它污染的是**所有**後續數字。
排在 P2 而非 P1，是因為 P1 的報告機制必須先存在才有東西可套用準則。

**Independent Test**: 給定一組候選標的與其盤前可得的客觀屬性，
執行準則後得出納入清單；變更任一標的的評估**結果**不改變納入結果。

**Acceptance Scenarios**:

1. **Given** 一組候選標的，**When** 套用納入準則，
   **Then** 納入決定僅依賴評估期間**開始前**即可得知的屬性，不依賴任何回測產出。
2. **Given** 同一組候選標的與同一準則版本，**When** 重複套用，
   **Then** 納入清單相同。
3. **Given** 某標的因不符準則被排除，**When** 檢視報告，
   **Then** 報告載明該標的被排除及其未達的具體準則項，而非靜默略過。
4. **Given** 納入準則被修改，**When** 執行評估，
   **Then** 報告記錄準則版本，使新舊結論不會被誤當成同一條件下的對照。

---

### User Story 3 - 歷史累積以解鎖樣本外切分 (Priority: P3)

由於資料源僅提供 60 天回溯，評估流程需**跨執行累積歷史**，
使可用窗口隨時間增長；當累積長度足以切出所需的訓練/測試組數時，
評估自動由「樣本內描述性」升級為「含樣本外驗證」。

**Why this priority**: 修掉缺陷 1，但它是**時間函數**——即使今天實作完成，
仍需數個月累積才會產生第一組有效的樣本外結論。故必須先有 P1/P2
讓期間的評估仍然可用，而非等待 P3 才開始產出。

**Independent Test**: 以合成的多期快照模擬累積，驗證合併結果無重複列、
無時序倒錯；並驗證超過保留期的鏈結中斷會被偵測而非被靜默吞掉。

**Acceptance Scenarios**:

1. **Given** 兩份時間範圍重疊的快照，**When** 併入累積歷史，
   **Then** 重疊時段不產生重複列，且合併後索引嚴格遞增。
2. **Given** 兩份快照對同一時間戳給出不同數值（資料源飄動），**When** 併入，
   **Then** 系統採用一致且有記錄的取捨規則，並記錄該衝突的發生次數。
3. **Given** 前次累積歷史已逾保留期而取不回，**When** 執行評估，
   **Then** 流程明示累積鏈已中斷、自何時重新起算，而非靜默從零開始並照常出報告。
4. **Given** 累積歷史長度不足以切出所需組數，**When** 執行評估，
   **Then** 報告明示「尚不足以進行樣本外驗證」並量化差距，
   而非退化為靜默的樣本內結論。
5. **Given** 累積歷史長度已足夠，**When** 執行評估，
   **Then** 報告產出逐窗口的訓練/測試結果，且測試窗口彼此不重疊。

---

### User Story 4 - 參數時框語意：待驗證問題而非既定需求 (Priority: P4)

現行參數（`ma_period`、`atr_period`、硬編碼的 `structure_period=10` 等）
在日線與 5 分線下代表完全不同的時間跨度。評估流程需**量測**此差異是否
實際造成問題，而非預設它造成問題。

**Why this priority**: 這是四項中唯一**尚未證實其存在**的問題。
現有量測反而不支持它：四道濾網通過率皆在正常範圍。
排最後是為了防止把假設當需求實作——若量測顯示無影響，正確產出是
「移除該假設」而非「實作時框化」。

**Independent Test**: 在固定快照上對週期參數做尺度掃描，
輸出各道濾網通過率與交易數對尺度的反應曲線；曲線平坦即為「無影響」的證據。

**Acceptance Scenarios**:

1. **Given** 一份盤中快照，**When** 對週期參數執行尺度掃描，
   **Then** 輸出各尺度下的逐道通過率與交易數，供判斷敏感度。
2. **Given** 掃描結果顯示某參數的尺度變化不改變結論，**When** 產生報告，
   **Then** 報告明確記錄「該參數在本資料上不構成瓶頸」，構成推翻假設的證據。
3. **Given** 掃描結果顯示某參數為瓶頸，**When** 產生報告，
   **Then** 報告指出該參數與其影響幅度，作為後續規格的輸入；
   本規格**不**實作參數時框語意變更。
4. **Given** 現行 `run_5m_evaluation.py` 在交易數不足時輸出「先做參數時框化」，
   **When** 本規格實作完成，**Then** 該處方改為由量測結果驅動，
   不得在無證據時輸出既定處方。

---

### Edge Cases

- **標的在評估期間停牌或長期無成交**：日內根數遠低於同期其他標的。
  應由納入準則於事前排除，而非在報告階段才發現。
- **資料源回傳的期間短於請求期間**：實測 `period="60d"` 得 59 交易日。
  報告需以**實得**期間為準敘述，不得以請求期間敘述。
- **累積歷史出現跨度斷裂**（排程中斷、artifact 逾期）：切分時不得跨越斷裂假裝連續。
- **納入標的數為 0**：準則過嚴時應明確失敗並回報，不得產出空報告當成結論。
- **暖機期吃掉整份資料**：若 `ma_period` 等長週期參數的暖機根數逼近總根數，
  可用判定根數趨近 0，此時所有通過率都失去意義，報告需擋下而非照算。
- **同一標的在不同快照版本下結論反轉**：屬資料飄動的預期後果，
  報告需能以指紋回溯是哪一份快照產生哪一個結論。

## Requirements *(mandatory)*

### Functional Requirements

#### 報告與可重現性

- **FR-001**: 評估流程 MUST 對每個標的獨立輸出統計，不得僅輸出跨標的合計值。
- **FR-002**: 任何跨標的合併的統計值 MUST 同時呈現其離散度（至少含極小值、
  極大值與兩者比值），使 pooling 隱含的同質性假設可被讀者當場檢驗。
- **FR-003**: 給定相同的輸入快照與相同的參數，評估流程 MUST 產出逐欄相同的數值輸出
  （確定性；不含執行時間戳等非結論欄位）。
- **FR-004**: 評估流程 MUST 於報告中記錄每份輸入快照的內容指紋，
  使任一結論可回溯至產生它的資料版本。
- **FR-005**: 所有績效類數字（報酬、最大回撤、獲利因子、勝率、期望值）
  MUST 附帶效力標籤；在通過樣本外驗證前，標籤 MUST 為「樣本內描述性統計」。
- **FR-006**: 評估流程 MUST NOT 輸出任何形式的策略有效性宣稱
  （憲章原則 III；含「可用」「有效」「建議啟用」等措辭）。

#### 零交易的可解釋性

- **FR-007**: 當某標的完成 0 筆來回交易時，評估流程 MUST 將其分解至下列互斥成因之一：
  (a) 無結構訊號；(b) 有結構訊號但五道合取為 0；(c) 有候選但全數因持倉互斥被跳過；
  (d) 有進場但於資料結束前未出場。
- **FR-008**: 評估流程 MUST 分方向計算結構訊號數（看漲／看跌分列），
  且該基數 MUST 與逐道流失分析的基數一致。

#### 標的納入準則

- **FR-009**: 標的納入 MUST 由具名、可版本化的客觀準則決定，
  準則的輸入 MUST 僅限評估期間開始前即可得知的屬性。
- **FR-010**: 納入準則 MUST NOT 引用任何回測或訊號產出作為輸入（避免選擇偏誤）。
- **FR-011**: 被排除的標的 MUST 於報告中列出並載明未達的具體準則項。
- **FR-012**: 報告 MUST 記錄本次套用的準則版本識別。

#### 歷史累積與樣本外切分

- **FR-013**: 評估流程 MUST 能將多次執行取得的快照併入一份累積歷史，
  合併結果的時間索引 MUST 嚴格遞增且無重複列。
- **FR-014**: 當兩份快照對同一時間戳給出不同數值時，系統 MUST 依一致且有記錄的
  取捨規則處理，並記錄衝突發生次數（資料源飄動為已知現象）。
- **FR-015**: 評估流程 MUST 依累積歷史長度判定是否足以進行樣本外切分；
  不足時 MUST 明示不足並量化差距，MUST NOT 靜默降級為樣本內結論。
- **FR-016**: 足以切分時，測試窗口彼此 MUST NOT 重疊，
  且 MUST NOT 跨越累積歷史中的時間斷裂。
- **FR-022**: 累積機制的執行頻率 MUST 顯著低於保留期上限（90 天），
  使單次排程失敗不致造成累積鏈斷裂。
- **FR-023**: 當前次累積歷史無法取回時（逾期、遺失、首次執行），
  流程 MUST 明示鏈結中斷與重新起算時點，MUST NOT 靜默從零開始。
- **FR-024**: 現行 `.github/workflows/probe_yfinance_5m.yml` 的快照上傳行為
  MUST 併入本累積機制，成為單一路徑而非兩套並行的快照產生方式。

#### 參數尺度敏感度

- **FR-017**: 評估流程 MUST 支援對週期參數的尺度掃描，
  輸出各尺度下的逐道濾網通過率與完成交易數。
- **FR-018**: 關於「參數是否需時框語意」的結論 MUST 由 FR-017 的量測驅動；
  流程 MUST NOT 在無量測支持時輸出既定處方。

#### 範圍與隔離

- **FR-019**: 本評估流程 MUST NOT 改變 `monitor_signals.py`、`backtester.py`
  或任何生產路徑的現行行為；日線生產路徑的逐筆、逐根輸出須與實作前相同。
- **FR-020**: 本規格 MUST 僅涵蓋現貨標的；期貨盤中資料無合乎授權的免費來源，
  明列為範圍外。
- **FR-021**: 評估流程 MUST NOT 將任何可調參數硬編碼於程式中（憲章原則 V）；
  現行 `structure_period=10` 的硬編碼屬**既有缺陷**，本規格 MUST 於報告中
  顯式標示其為硬編碼值，但修正其來源不在本規格範圍內。

### Key Entities

- **快照（Snapshot）**：某標的在某次取數所得的盤中 OHLCV 序列，
  帶時間範圍與內容指紋。是可重現性的最小單位。
- **累積歷史（Accumulated History）**：同一標的多份快照合併去重後的序列，
  帶合併記錄（衝突次數、斷裂位置、起算時點）。是樣本外切分的輸入。
- **納入準則（Inclusion Criteria）**：一組客觀、事前可判定的條件與其版本識別。
- **標的評估結果（Per-Ticker Result）**：單一標的的資料體質、訊號密度、
  逐道流失、交易樣本量與零交易成因分解。
- **效力標籤（Validity Label）**：附著於每個績效數字的推論邊界宣告。
- **窗口切分（Window Split）**：訓練/測試期間的具體邊界與其不重疊保證。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同一份快照連續執行兩次，報告的數值欄位 100% 逐欄相同。
- **SC-002**: 報告中 100% 的績效類數字帶有效力標籤；無標籤者為缺陷。
- **SC-003**: 任一跨標的合併數字，讀者可在同一畫面看到其離散度，
  無需另行查閱逐標的表格。
- **SC-004**: 對任一完成 0 筆交易的標的，報告可指出其唯一成因分類；
  以現有已知的三檔（2330 / 2454 / 2308）驗證，三檔皆須得到分類，
  不得有「原因不明」。
- **SC-005**: 納入清單對評估結果的擾動不敏感——人為改變任一標的的回測輸出，
  納入清單不變。
- **SC-006**: 被排除標的的排除理由 100% 可追溯至具體準則項。
- **SC-007**: 兩份時間重疊的快照合併後，重複列數為 0、時序倒錯數為 0。
- **SC-008**: 當累積長度不足時，報告明示不足並給出量化差距（還差幾個交易日）；
  當足夠時，測試窗口重疊數為 0。
- **SC-009**: 累積鏈中斷（取不回前次歷史）時，報告 100% 明示中斷與重新起算時點。
- **SC-010**: 尺度掃描可對至少一個週期參數輸出完整的反應曲線，
  使「該參數是否為瓶頸」成為可讀出的結論而非推測。
- **SC-011**: 日線生產路徑的回測輸出（逐筆、逐根、逐欄）與本規格實作前完全相同。
- **SC-012**: 報告中「策略有效性宣稱」的出現次數為 0
  （以既定措辭清單檢核；憲章原則 III）。
- **SC-013**: `pytest` 全綠，且本規格每一條驗收標準對應至少一個測試，
  無法自動化者標註 `[MANUAL]` 並附人工驗證步驟。

## Assumptions

- **評估仍屬研究路徑，不入生產**。與 `run_b_segment.py`（B 段實測）同性質：
  組態覆寫在記憶體內、不寫回 `config/config.yaml`、不入 DB。
- **現行 8 檔實測結果不具追溯效力**。它們由事後挑選的標的產生，
  本協定建立後須以新的納入準則重跑；舊數字僅作為方法論的反例保留於 review 文件。
- **樣本外驗證的解除門檻**採下列預設：至少 3 組互不重疊的測試窗口，
  且每個測試窗口內每標的至少 30 筆來回交易。未達此門檻前，
  效力標籤維持「樣本內描述性統計」。此門檻可被後續規格修訂，但須明示並記錄版本。
- **累積機制的排程頻率**預設為每週一次——遠低於 90 天保留期上限，
  單次失敗不致斷鏈，且與 `alert_scheduler.yml` 既有的 Actions 排程慣例一致。
- **納入準則的預設維度**（具體閾值於規劃階段決定）：日內成交量水準、
  資料完整度（盤中缺口數）、每日根數穩定度、價格檔位粒度。
  槓桿型與反向型 ETF（如 `00631L.TW`）之複利路徑相依性與一般現貨不同，
  預設為個別討論而非直接納入。
- **資料源飄動的取捨規則**預設採「先到者為準」（既有累積值不被後續取數覆寫），
  理由是可重現性優先於新鮮度；衝突次數仍須記錄以便發現異常。
- **`structure_period=10` 的硬編碼**（`backtester.py:209`、`monitor_signals.py`）
  為既有缺陷，本規格只標示、不修正——修正它會動到生產路徑，違反 FR-019。
- **執行入口**預設沿用並取代 `run_5m_evaluation.py`：該檔為本協定的原型，
  其資料體質、參數尺度對照、逐道流失三段可直接沿用；
  其 `verdict` 段的既定處方須依 FR-018 改寫。
- **依賴**：yfinance（已在相依清單內）、`ladder_system.build_indicator_frame`、
  `backtester.BacktestEngine`、`performance.infer_periods_per_year`。
  不新增外部付費資料源。

## Out of Scope

- **台指期盤中評估**。FinMind 的 `TaiwanStockKBar` 與 `TaiwanFuturesTick`
  皆需付費贊助層級（run `30997571949` 實測），yfinance 無台指期 5m。
  無合乎授權的免費來源前，期貨盤中不在範圍內。
- **參數時框語意的實作**。本規格只量測其必要性（FR-017/018），不改參數模型。
- **`structure_period` 硬編碼的修正**。動到生產路徑，另立規格。
- **盤中訊號進入 `monitor_signals.py` 推播或 `backtester.py` 生產回測**。
  本規格為評估協定，不改變任何生產行為。
- **策略調參與最佳化**。在樣本外驗證機制成立前進行盤中調參即為過擬合。
- **Yahoo 資料再散布疑慮的根本解決**。D1 已記錄該風險經裁決接受而非消解；
  真正的解法是取得合乎授權的分鐘級資料源，不在本規格範圍內。
